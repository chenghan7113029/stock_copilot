<title>投资Agent</title>

当前设想下来，在整个投资方面应该由各个智能体帮我接管，在不同的场景有不同的细节管理方式，然后有个全局总览的Agent来负责一些总的规划和筹办，一大堆智能Agent Team组合在一起构成了我自己的私人投顾。整个投资领域可能覆盖股票、基金、债券、存款等形式。

## 架构设计理念

**Agent 不做“最终拍板人”，只做“专业幕僚+执行记录员”；人类保留投资委员会（IC）与家族理事会（FC）的否决权与签字权。**

架构 = 人类治理层 + 总控编排层 + 专业职能 Agent + 审计留痕层。

# 一期：投资 Agent 先解决什么（基于 2020–2026 历史复盘）

> 一句话：历史数据说明，问题不在选股，在四个地方——买点靠感觉、亏损单不卖、卖完就空仓、账本记不清。一期只做其中「不需要预测未来」的部分；凡声称能预测的能力（买点、择时、荐股），一律先通过样本外验证再上线。

## 一、复盘暴露的六个问题

| # | 问题 | 证据（可复算） | 已造成的代价 |
|-|-|-|-|
| P1 | 买点靠感觉，高位越跌越买 | 上海机场 72 → 57.59 → 57.59 → 47.2 → 40.46，四次加仓，均价 52.2 | 2025-12 清仓亏 25.39 万，约 -49% |
| P2 | 亏损单不卖，等回本 | 盈利单中位持有 68.5 天，亏损单 512 天；6 年 63 笔里只有 3 笔亏损单 | 「95% 胜率」是假象；上海机场一只吃掉全部盈利的 36% |
| P3 | 卖完就空仓，没有替代方案 | 2025-12 清仓后权益占比从约 25% 降到 4.04%，约 672 万停在 1.6% 存款 | 目标权益 35%，缺口 217 万；等待 11 个月无规则 |
| P4 | 没有决策留痕 | 63 笔里只有 2 笔记录了大盘点位；无买入理由、无预设止损线 | 无法归因，无法复现，无法改进 |
| P5 | 账本不可信 | 「持仓价值」列等于成本；出现 2020-01-01 占位日期；手续费多为空 | 要回答「我现在赚没赚」得人工重算 |
| P6 | 没有验证能力 | 任何规则都无法用历史数据检验，只能靠直觉 | 规则要么拍脑袋，要么干脆不写 |

口径：已平仓 63 笔合计 +812,026 元；2025-12 四只清仓合计 -68,778 元（上海机场 -15 万、保利 -2.4 万、华发 +10 万、三一 +5,222）；当前 5 只持仓浮亏 -46,409 元；全期合计 +414,349 元（2020-01 至 2026-11，未计分红与税费）。

## 二、先分清两类问题

| 问题 | 是否声称能预测未来 | 一期能否直接做 |
|-|-|-|
| P1 买点 / 择时 / 荐股 | 是 | 否。必须先做样本外验证，否则与拍脑袋无异 |
| P2 单笔最大损失 | 否（是风险预算约束，不是收益主张） | 能。只承诺「亏损被限制在 X」，不承诺「收益更高」 |
| P3 配置比例与投放节奏 | 否 | 能。目标比例来自风险预算，定投是对「无法择时」的承认 |
| P4 决策留痕 | 否 | 能 |
| P5 账本与市价 | 否 | 能 |
| P6 验证基础设施 | — | 能，且是 P1 的前置条件 |

## 三、一期优先级

| 优先级 | Agent 能力 | 解决的问题 | 验收标准 |
|-|-|-|-|
| P0 | 持仓体检 + 止损门禁 | P2 | 5 只持仓逐只输出「持有 / 减仓 / 清仓」与触发条件；任一持仓跌破成本 -15% 或连续 5 日收于 MA60 下方，次日必须进入待办，不可静默跳过 |
| P0 | 配置执行器 | P3 | 每月固定日给出「买什么类别、买多少」；权益不超过 40%、单票不超过 5%、行业不超过 25% 三条上限可校验；偏离超 5pp 触发再平衡提示 |
| P0 | 账本与市价 | P5 | 任意时刻能回答：总权益、各标的市值、浮盈浮亏、占比、数据时效；不再出现「持仓价值等于成本」 |
| P1 | 决策留痕 | P4 | 每笔买卖附：买入理由、买入位置、预设止损线、事后归因；季度可出一份归因报告 |
| P1 | 事件研究与回测 | P6 | 预注册假设加样本外验证；输出「哪些条件有信息量、哪些没有」，允许结论是「无信号」 |
| P2 | 候选池与买点条件 | P1 | 仅在 P1 验证通过后启用；未通过的只作观察指标，不产生动作 |

## 四、为什么是这个顺序

1. P0 三件都不需要预测未来，因此现在就能做，不存在「没回测就不敢用」的问题，也不会把未经验证的直觉写进系统。
2. P0 直接对应已经发生的损失：上海机场的 25.39 万来自「不设止损加高位加仓」，217 万缺口来自「清仓后无规则」，账本失真来自「没有市价口径」。
3. P1 的验证层是 P2 的前置条件：没有它，任何买点规则都只能靠感觉，这正是过去六年的问题。

## 五、一期明确不做

- 全市场荐股排序（需要截面因子与回测，属于 P2 之后）
- 宏观 / 政策研报、债券研究员（数据与验证成本高，非当前瓶颈）
- 交易员自动下单（只出工单，人工执行）
- Web UI（CLI 与对话足够）

## 六、与现有团队角色的映射

| 文档中的角色 | 一期对应能力 | 状态 |
|-|-|-|
| 风控专员 | 止损门禁与三条上限校验 | 先做（P0） |
| 基金经理 | 配置执行器（只管比例与额度，不选个股） | 先做（P0） |

## 七、一期完成的定义

- [ ] 能在 3 分钟内回答「我现在该做什么」：加仓、减仓或不动，以及金额与触发条件

- [ ] 任一持仓触发止损线，次日出现在待办中，且无法被静默忽略

- [ ] 每月定投金额可复算，且与 ips 配置一致

- [ ] 每笔交易有留痕，季度能出一份可读的归因

- [ ] 至少一个买点条件通过样本外验证，或明确得出「无信号」的结论

## 八、待确认

- 验证的验收门槛：样本外 t 值、分年度胜率、样本量的具体阈值
- 权益目标是否维持 35%，投放期限 12 / 24 / 36 个月选哪个
- 止损线定在成本 -15%，还是另有口径（例如组合层面回撤优先）
- 账本的权威数据源：手工录入、券商导出，还是接口同步

# 回测模块（一期 P0）

> 一句话：没有回测，前面所有规则（止损线、持仓上限、加仓限制）都只是另一个人拍脑袋，不比直觉更高明。这个模块的产出不是「圣杯」，而是帮你删掉九成念头。

## 一、为什么它排第一

止损、上限、调仓阈值都属于经验命题：它们声称能改变交易结果，就必须有证据。此前的回放已经说明问题——同一批交易，-15% 止损净亏 5.2 万，-25% 反而净赚 2.9 万，MA60 在 81 笔里触发 80 次、净亏 29.7 万。阈值一动结论就翻，正是「没有回测就只能拍脑袋」的证据。

## 二、八条硬约束

| # | 要求 | 具体做法 |
|-|-|-|
| 1 | 预注册 | 先写假设、参数、评价指标并提交 git，再跑数据；跑完不许改假设，只能新开一次实验 |
| 2 | 样本切分 | 训练 2015–2020、验证 2021–2023、样本外 2024–2026；样本外只允许跑一次，跑完即「烧掉」 |
| 3 | 多重比较 | 报告一共试了几个规则（K），用 Bonferroni 或 Deflated Sharpe 校正；未报告 K 的结果一律不采信 |
| 4 | 成本与摩擦 | 佣金、卖出印花税、按成交额分层的滑点、涨跌停不可成交、停牌跳过、T+1 |
| 5 | 无未来函数 | 信号用 t 日收盘，成交用 t+1；财务数据按公告日对齐，不用报告期 |
| 6 | 生存偏差 | 样本包含退市与 ST；指数成分使用历史成分，不用今天的成分回看过去 |
| 7 | 基准与归因 | 任何规则都要与买入持有、市场组合对比；收益拆出 beta、规模、价值、动量 |
| 8 | 稳定性 | 分年度、分牛熊震荡、分市值组，检查是否只在某一段有效 |

## 三、A 股特有的五个坑

| 坑 | 后果 | 处理 |
|-|-|-|
| 涨跌停 | 信号触发但一字板买不进或卖不出，回测高估收益 | 当日封板则订单失败，顺延到下一个可成交日 |
| T+1 | 当日买入不能卖，日内止损在 A 股不存在 | 信号与成交至少隔一个交易日 |
| 复权口径 | 前复权会随新分红改写历史价格，产生假信号 | 使用后复权，或分段复权并在分红日调整 |
| 财报滞后 | 用报告期当公告日即为未来函数 | 年报 4 月底、季报 4/8/10 月底，按实际公告日对齐 |
| 流动性 | 小市值股回测能成交，实盘买不到量 | 按日均成交额分档设置单笔上限与滑点 |

## 四、样本怎么选：三层结构

直接回答「单票太小、全市场太泛」：全市场回测把异质性当噪音，单票回测把噪音当信号。正确解法是分层，而且三层回答的是不同问题，不能互相替代。

| 层级 | 样本 | 回答什么问题 | 自由度 |
|-|-|-|-|
| L0 大盘 | 指数与全市场截面 | 仓位与择时：权益要不要 35%、什么时候降 | 最低 |
| L1 同质组 | 相似标的集合（数十只 × 多年） | 这类标的上，某条规则是否成立 | 中 |
| L2 个股 | 单只标的 | 组内相对排序，不预测绝对收益 | 最高，样本最小 |

## 五、相似组怎么找

1. 只用可计算、可复现的特征：规模（流通市值分位）、价值（PB/PE 分位）、质量（ROE 与经营现金流）、波动（beta 或 60 日波动分位）、股息率、动量（过去 12 个月）。
2. 用分位切点分组（例如三分位 × 三分位 = 9 组），不用行业标签：行业分类会变动、彼此不互斥，而且分类本身带主观判断。
3. 组要够大：每组至少 30 只、时间跨度至少 3 年，组数控制在 9 到 27 之间；组数越多，单组样本越薄。
4. 每季度重算分组，但不得回改历史分组——用今天的分组回看 2015 年，等于用未来信息。
5. 可以复用仓库已有的估值原型分类（service/value）作为语义骨架，但切点仍以分位为准，保证可复算。

判断分组是否有效，看两个数的比值：组内日收益相关中位数除以组间相关中位数。比值越大，说明「相似」抓住了真东西；如果组内组间差不多，说明这组特征没用，换一组。

### 标签体系：三类标签与控制方法

「组」的实质是给股票打的标签。标签必须同时满足三条：在 t 时刻可观测、可复现计算、有明确切点。缺一条就是未来函数。

| 类型 | 例子 | 能否进回测分组 | 原因 |
|-|-|-|-|
| 硬标签 | 市值分位、PB/PE 分位、营收与利润增速分位、ROE、股息率、上市年限、波动率分位、动量 | 能 | t 时刻可观测，可复算 |
| 软标签 | 主题归属、产业链位置、行业生命周期、管理层评价 | 不能直接进，先登记后检验 | 主观、事后可变，容易后视镜 |
| 结果标签 | 被主力资金青睐、后面涨了 | 不能用 | 这是结果不是原因，等于抄答案 |

### 把「热门题材 / 夕阳行业」变成可测变量

这两个是典型的后视镜标签：你现在知道它热，是因为它已经涨了。改用当时可观测的代理指标：题材 → 换手率分位、成交额分位、板块资金净流入排名；夕阳 → 行业营收增速分位、行业资本开支持续下降的年数。代理指标是数据，不是印象，而且天然带时间戳。

### 控制组合爆炸

1. 先单后双：每个标签单独分层跑一遍，只有显著的单标签才进入二维交叉。
2. 组数上限 9 到 27：一维 3 档、二维 3×3，不要三层以上。
3. 部分池化：小组的估计向全局均值收缩，否则小样本组会冒出大量假阳性。
4. 检查标签共线：小市值、高波动、高换手、题材热往往说的是同一件事，相关性超过 0.7 的标签应合并。

### 软标签也要登记

人工打标签时必须记录：标签、时间、理由。半年后回看这批标的的后续 60 日超额，检验这个判断在哪些条件下有效。这是把直觉登记成可检验变量，不是用数据替换直觉。

### 产出形态

| 规则 | 标签维度 | 分档 | 效应（相对买入持有） | 样本量 | 结论 |
|-|-|-|-|-|-|
| -20% 止损 | 股息率 | 高 | +3.1% | 420 | 有效 |
| -20% 止损 | 股息率 | 低 | -8.4% | 510 | 有害 |
| -20% 止损 | 波动率 | 高 | -12.0% | 380 | 显著有害 |

要得到的是「在你的持仓类型上该不该止损」，而不是「该不该止损」。

风险提示：如果在几百个组合里挑最好的三个，那就是多重比较灾难。标签与切点必须在看结果之前定好，并报告一共试了多少个组合。

v1 建议先引入三个硬标签：市值分位、股息率分位、波动率分位；软标签只登记、不参与回测，攒够半年样本再评估。

## 六、从组到个股：部分池化

不要相信单票的独立估计（样本太少），也不要用组均值一刀切（忽略了它自己的证据）。做法是把个股效应向组均值收缩：样本少时结果靠近组，样本多时靠近个股本身。统计上叫部分池化，等价于给每只股票一个以组为单位的先验。

落地形式：对每只股票输出「组内分位」，而不是「绝对收益预测」。组内排序比绝对预测稳健得多，也直接可用——买组内前 20%，而不是买「我觉得会涨的那只」。

## 七、三个统计陷阱

- 组内相关：同组股票同涨同跌，名义样本三千，有效样本可能只有几十个时间块。必须用 block bootstrap 或 cluster-robust 标准误，否则 t 值虚高。
- 分组本身也是多重比较：size 三分位不行换五分位，换过几次都要计入 K。
- 用未来信息分组：先知道它后来涨了，再回头归到「强势组」，是典型后视镜。

## 八、工程形态

```text
src/service/backtest/
├── data.py      # 本地 kline + 财务，按公告日对齐，后复权
├── universe.py  # 历史成分、退市股、分组切点（按季度重算）
├── signal.py    # 纯函数：输入 t 日之前的数据 → 输出动作（天然防未来函数）
├── broker.py    # 撮合：成本、涨跌停、T+1、停牌
├── metrics.py   # 收益、回撤、换手、分年度、分组归因
└── registry.py  # 实验台账：假设、参数、K、样本区间、结果
```

两条关键设计：信号函数必须是纯函数，不允许访问 t 日之后的数据；实验台账必须每次落一行，否则三个月后会忘记自己试过多少次。

## 九、验收：三级门禁

1. 回测通过：样本外、扣成本、多重比较校正后，不劣于基准。
2. 影子运行：规则只输出建议、不进入执行，记录 6 到 12 个月的实际表现。
3. 实盘启用：影子期与回测结论方向一致，才允许进入小仓位执行。

跳过任何一级，就等于回到拍脑袋。

## 十、MVP 与校准

第一版不做全策略回测，先做事件研究：给定条件成立，统计之后 20 日与 60 日相对基准的超额分布。自由度低，不容易过拟合。

用一道已知答案的题校准台子：拿「跌破 MA60 止损」跑全 A 股，预期它显著跑输买入持有（在个人 81 笔样本上已知净损 29.7 万）。如果台子复现不出这个结论，先修台子，不要相信它的任何输出。

台子可信之后，依次测：禁止亏损加仓、单票上限、再平衡阈值。这几个都针对已知的行为问题，且不含技术指标。
