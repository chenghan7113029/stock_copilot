## 1. 执行摘要

**stock_copilot** 是个人股票投资助手，目标不是替代用户做买卖决定，而是：

1. **补齐信息面** — 系统收集并结构化「公司长期价值、短期市场波动、市场情绪」三维信息，降低因信息缺失导致的误判；
2. **降低决策偏差** — 通过红蓝对抗、无仓位视角、结构化 Checklist 等机制，在用户做决定时充当「审计镜」，对抗确认偏差、沉没成本、锚定效应等常见认知陷阱；
3. **支撑全周期** — 覆盖交易前（多维看板）、交易中（决策审计）、交易后（复盘归因）的完整闭环。

**一句话定位：** 三维信息收集 + 决策护航审计 + 可复盘进化的个人投资 Copilot。

## 2. 产品目标

| 目标维度 | 描述 | 可衡量方向（后续细化 KPI） |
|----------|------|---------------------------|
| 精准度 | 改善买卖时机与标的选择质量 | 决策后 N 日胜率、相对基准超额 |
| 风控 | 减少不合理买卖与深套 | 止损执行率、违背 Checklist 的交易占比 |
| 纪律 | 克服情绪化与路径依赖 | Checklist 完成率、复盘归因覆盖率 |
| 可解释 | 每个结论可追溯至数据与方法论 | 报告含价值/技术/情绪分项及依据 |

**不承诺：** 保证盈利、替代专业投顾、提供内幕或非公开信息。

## 3. 目标用户与典型场景

### 3.1 用户画像

- **主用户：** 具备基本投资常识的个人投资者，自主决策、自行下单；
- **特征：** 能阅读财报与 K 线，但易在恐慌/贪婪中偏离纪律；曾出现「只看好消息」「被套加仓」「盯历史最高价」等行为；
- **技术接受度：** 愿意使用 Web/CLI 看结构化报告，接受 LLM 辅助但需确定性数据支撑。

### 3.2 典型场景（User Stories）

| ID | 场景 | 期望行为 |
|----|------|----------|
| US-01 | 考虑买入一只下跌中的「便宜」股票 | 看到价值面估值区间 + 技术面是否接飞刀 + 情绪是否极端恐惧，而非仅因 PE 低而买 |
| US-02 | 持仓被套，犹豫是否加仓 | 触发「假设今日首开仓」评估，隐藏成本价与盈亏百分比，强制无仓位视角回答 |
| US-03 | 大涨后想追涨 | 情绪量化显示极端贪婪 + 红蓝军空方报告，提醒过热与趋势钝化风险 |
| US-04 | 提交买入前 | 必须完成 Checklist（价值理由 ≥2 条、技术面配合、情绪位置、止损止盈）；仅「昨晚看新闻」则拦截 |
| US-05 | 一笔交易结束后 | 进入复盘：胜率统计 + badcase 偏差归因，规则反哺后续 Checklist |

## 4. 问题陈述与产品哲学

### 4.1 核心问题

1. **信息面缺失：** 决策时未同时审视价值、趋势、情绪，导致片面结论；
2. **人类决策偏差：** 确认偏差、沉没成本谬误、锚定效应、路径依赖、可得性启发等系统性扭曲判断；
3. **缺乏审计与复盘：** 交易前无强制结构化思考，交易后无偏差归因，错误模式重复发生。

### 4.2 三维分析框架（产品认知基础）

股价短期表现受三类因素共同作用，**Copilot 须分别量化并综合呈现**：

```text
┌─────────────────────────────────────────────────────────┐
│                    投资决策输入                           │
├─────────────┬─────────────────────┬─────────────────────┤
│  价值面      │  技术面（波动/钱流）  │  情绪面              │
│  公司长期价值 │  择时·趋势·止损      │  贪婪/恐惧·抱团·拐点   │
└─────────────┴─────────────────────┴─────────────────────┘
                              │
                              ▼
                    决策护航（偏差审计）
                              │
                              ▼
                      用户最终决策
```

**设计原则：**

- 单维结论不得替代综合判断（例：价值便宜但技术破位仍须警示）；
- 情绪是「短期警报器」非「长期导航仪」，须与技术反转、价值底价支撑联合解读；
- 决策护航**不替用户下单**，只提高决策过程的完整性与自省强度。

### 4.3 待补充信息面（开放项）

用户自述信息面可能有遗漏，后续 OpenSpec 变更中持续补充，候选包括：

- 宏观与政策事件（利率、行业监管、地缘政治）；
- 流动性与资金面（北向、ETF 申赎、板块轮动）；
- 公司治理与重大事件（减持、回购、诉讼）；
- 持仓组合相关性（单票决策对整体组合的影响；V1 已实现市值集中度与基于原始行业文本的暴露度粗估，不含协方差/组合优化）。

## 5. 能力域与模块映射

### 5.1 信息收集模块

#### 5.1.1 价值面分析

| 项 | 内容 |
|----|------|
| **要解决的问题** | 买股票即买公司一部分：识别公司合理价值，在价格显著低于价值时发现机会 |
| **用户价值** | 过滤垃圾股/暴雷风险；计算安全边际；大跌时提供「核心竞争力未变」的长期持有依据 |
| **能力期望** | 基于公开数据与估值方法，产出**合理估值区间**及价值面价格判断 |
| **方法论范围** | 宏观行业（PEST、波特五力）；商业模式与护城河（Moat、治理）；财报分析（盈利、负债、现金流）；估值（PE/PB/PS 相对估值、DCF 等绝对估值） |
| **已知短板** | 价值陷阱：便宜但长期不受市场认可（「死等」） |
| **缓解策略** | 与技术趋势、情绪冰点组合判断；价值面输出须含「市场认可度假设」与置信度 |
| **实现参考** | `valueinvest/`、`FinanceToolkit/`；详见 [features/value-analysis.md](features/value-analysis.md) |

#### 5.1.2 技术面分析

| 项 | 内容 |
|----|------|
| **要解决的问题** | 顺应钱流与趋势，提高择时与资金效率 |
| **用户价值** | 避免下跌通道接飞刀；识别压力/支撑；趋势跟随；**机械化止损**（如跌破关键均线） |
| **能力期望** | 基于公开行情数据，评估**短期趋势**与买卖时机信号 |
| **方法论范围** | K 线形态；趋势线与 MA；MACD/KDJ/RSI；量价关系（放量、背离、缩量） |
| **已知短板** | 主力诱多/诱空导致频繁止损 |
| **缓解策略** | 与价值底价、情绪极端组合；止损规则写入 Checklist 且可复盘 |
| **实现参考** | `daily_stock_analysis/`（MA/MACD/RSI/量能、YAML 策略） |

#### 5.1.3 情绪因素量化

| 项 | 内容 |
|----|------|
| **要解决的问题** | 将「市场很热/很绝望」从感性转为可度量指标 |
| **用户价值** | 极端拐点（底部/顶部警报）；抱团与动能强度；客观镜子克服从众心理 |
| **能力期望** | 输出情绪分位/等级，并标注与技术、价值面的**联合解读建议** |
| **方法论范围** | 衍生指标（融资融券、涨跌停与连板、VIX/认沽认购比、恐慌贪婪指数等）；文本挖掘（社媒、新闻情感）；龙虎榜与席位 |
| **已知短板** | 情绪过热/过冷可持续较久（情绪钝化），单独使用易被打脸 |
| **缓解策略** | **强制**在报告中标注：须结合技术面反转确认 + 价值面底价支撑；禁止单独作为买卖唯一依据 |
| **实现优先级** | P1（V1 已实现：涨跌停家数比 + 恐慌贪婪代理指数；个股融资余额、龙虎榜、社媒文本挖掘待后续迭代） |

### 5.2 决策护航模块（认知偏差审计）

> **定位：** 不替用户做决定，在用户做决定时「举起镜子」。

| 偏差 | 表现 | Copilot 机制 | 优先级 |
|------|------|--------------|--------|
| **确认偏差** | 持仓后只看好消息 | **红蓝军对抗**：多空角色基于同一公开信息各出报告并互相攻击；用户须声明拒绝哪方及理由。**V1（Skill 版）已实现**：`report dual` 证据分桶 + Cursor Skill 互驳叙事；用户声明留痕与 Web + 独立 LLM API 版待建（依赖已冻结的 `add-llm-narrative-core`） | P0 |
| **沉没成本谬误** | 被套不舍割、盲目加仓摊薄 | **假设今日首开仓（已实现）**：CLI `position set` 录入最小当前持仓，严格离线 `entry-check` 隐藏持仓成本/盈亏比例，提问「若无仓位今日是否仍愿买入」；否 → 减仓/止损提醒 | P0 |
| **锚定效应** | 盯历史最高价或买入成本 | **V1 已实现：**分位定性分档呈现 + 历史最高价默认隐藏（需 `--show-anchor-price` 显式展示）；成本价隐藏留给 `add-fresh-entry-check` 复用本 change 的护栏惯例 | P1 |
| **路径依赖 / 可得性** | 只用曾经赚钱的一招；因昨晚爆款文章就想买 | **结构化 Checklist（已实现）**：CLI `checklist submit/show` 强制填写价值理由 ≥2、技术面配合、情绪位置、止损止盈；仅单条「新闻感觉」→ **硬拦截**，不合规尝试仍留痕 | P0 |

**Checklist 最低字段（买入/卖出均适用，后续 OpenSpec 细化）：**

- [x] 长期价值理由（≥2 条，须引用价值面输出）
- [x] 短期技术面配合情况
- [x] 当前情绪所处位置及解读
- [x] 明确止损点与止盈点
- [x] 非「可得性单一原因」（系统校验）

### 5.3 综合呈现与 LLM 层

## 6. 系统流程（全周期）

```text
交易前                交易中                 交易后
───────              ───────                ───────
信息沉淀              决策审计                复盘归因
· 价值/技术/情绪       · 红蓝对抗报告           · 历史决策胜率
· 多维看板            · Checklist 强制填写     · Badcase 偏差归因
· 估值区间与信号       · 首开仓/锚定防御        · 规则反哺 Checklist
                      · 拦截不合规申请
```

**流程约束（决策完整性）：**

1. **分析 → 审计 → 决策：** 用户声明交易意图前，应已加载该标的最新三维分析；
2. **审计不可跳过：** P0 阶段 Checklist 与红蓝对抗至少完成其一并留痕（具体交互 OpenSpec 定义）；
3. **复盘闭环：** 交易后记录进入 dao，定期生成偏差归因报告，可更新 Checklist 规则库。

## 8. 成功标准与验收准则

### 8.1 产品级

- [x] 单票一次请求可获得**价值 + 技术**分项报告及汇总看板（Phase 1 — CLI：`report tech/value/dashboard`；LLM 综合解读：`report summary --narrate`）
- [ ] 价值面输出含**估值区间、安全边际、价值陷阱风险提示**
- [ ] 技术面输出含**趋势判断、关键位、止损建议**
- [x] 买入/卖出意图触发 Checklist，缺字段或仅可得性原因时**系统拒绝提交**（Phase 2 — CLI `checklist submit`；不合规提交留痕）
- [x] 红蓝对抗报告对同一标的给出可对比的多空论述（Phase 2 — V1 Skill 版：`report dual` + Cursor Skill；Web/用户声明留痕待建）
- [x] 交易记录可生成 FIFO 胜率与平均已实现收益率；关联合规 Checklist 时可识别 Badcase（Phase 4 — `trade record` / `report trade-review`）
- [x] 情绪指标出现时，报告内**必须**含与技术/价值的联合解读段落（Phase 3 — `report dual`）

### 8.2 工程与文档

- [ ] MRD / Design 与 OpenSpec 归档同步（见 [docs/README.md](../README.md)）
- [ ] 确定性计算与 LLM 输出分离，数值可追溯至 data_provider / service 原始结果
- [ ] 关键决策（Checklist 填写、用户拒绝红蓝哪方）可持久化备查

### 8.3 非目标（明确排除）

- 不提供实盘下单、券商对接；
- 不替代 licensed 投资顾问；
- 不承诺收益或提供内幕信息；
- 不在无用户确认的情况下自动执行买卖。
