# Proposal: add-backtest-engine

## Why

没有回测台子，一期所有规则都只是「另一个人拍脑袋」。飞书《投资Agent》r482 把「回测模块（一期 P0）」排在一期第一位，理由是同一条规则换个阈值结论就翻——**同一批交易，-15% 止损净亏 5.2 万元，-25% 止损反而净赚 2.9 万元；「跌破 MA60 卖出」在 81 笔里触发 80 次，净亏 29.7 万元**（§回测模块·一「为什么它排第一」）。这三个数字说明：止损线、单票上限、调仓阈值都是**经验命题**，参数动一格结论就反向，没有可复现的验证流程，我们无法区分「规则有效」与「参数恰好」。

如果不做，直接后果有三条：① 一期 P0「持仓体检 + 止损门禁」将把**未经验证**的 -15% 阈值制度化（飞书 §三 一期优先级 P0）；② 飞书 §七「一期完成的定义」中「至少一个买点条件通过样本外验证，或明确得出『无信号』的结论」不可能达成；③ 下一波 Agent 策略讨论（买点、止损、仓位）没有共同事实基础，每条策略都要重新拍一次脑袋——这正是过去六年复盘暴露的第 6 个问题 P6「没有验证能力」。

仓库现状也没有替代品。`openspec/specs/` 现行 69 个 capability 没有一个能做历史验证：`trade-review-attribution` 只能对**已经发生**的成交做 FIFO 复盘，回答不了「换一条规则会怎样」；`portfolio-analyzer` 只算集中度。数据侧同样无法空手开工：三个数据源适配器一律取**前复权**（`src/data_provider/baostock/fetcher.py:363` `adjustflag="2"`、`src/data_provider/tushare/fetcher.py:295` `adj="qfq"`、`src/data_provider/akshare/fetcher.py:109`），而前复权会随新分红改写历史价、制造假信号（飞书 §三·复权口径）；本地 `kline` 表只有 OHLCV 五列，**没有成交额、涨跌停、停牌标记**（`src/dao/models.py:134`），做不了「按成交额分层滑点」与「封板不可成交」。

## What Changes

本波交付的是**回测台子**（数据对齐 + 撮合 + 指标 + 实验台账 + 门禁），**不是策略研究结论**。「-15% 止损是否有效」这类结论属于台子之上的一次实验，不在本 change。

- 新增 capability `backtest-engine`：19 条 Requirement，逐条覆盖飞书 §二 八条硬约束、§三 A 股五个坑、§五 标签与分组、§六 部分池化、§七 三个统计陷阱、§八 工程形态、§九 三级门禁、§十 MVP 与校准。Requirement 与来源锚点的映射见下表。
- 不改任何既有 capability 的 spec。`tech-analyzer` / `value-analyzer` / `data-fetcher-router` 作为**被消费的产出源**复用（只调用，不改其行为与 spec）。
- 不新增 LLM 环节：收益、回撤、t 值、滑点、K 计数等全部由确定性代码计算（`docs/dev/engineering-conventions.md` §9.2「禁止 LLM 生成或修改数值字段」）。
- 工程形态参考飞书 §八 的六件（data / universe / signal / broker / metrics / registry），但**落盘分层服从仓库约定**：领域编排进 `src/service/backtest/`，外部数据适配进 `src/data_provider/`（§八 是结构参考，最终模块划分以 T2 `design.md` 为准）。
- 本波只到设计：不写 `src/`、`test/` 代码，不改 `openspec/specs/`，不产 `knowledge-delta.md`，不改 `docs/mrd/`。

## Capabilities

### New Capabilities

- `backtest-engine`：一期 P0 的**历史验证台子**——把「假设 → 数据对齐 → 撮合（含 A 股约束与成本）→ 指标与归因 → 实验台账 → 门禁」做成可复算、可审计、可机检的一条链，产出「给定条件成立后 N 日相对基准的超额分布」这类结论，并允许结论是「无信号」。覆盖范围：预注册与台账、三段样本与样本外烧毁、多重比较校正、成本与摩擦、A 股撮合约束、后复权口径、无未来函数、生存偏差、基准与归因、稳定性分档、标签与部分池化、事件研究 MVP、已知答案校准、三级门禁。

### 与既有能力的关系

| 既有 capability | 关系 | 是否改其 spec |
| --- | --- | --- |
| `data-fetcher-router` | **复用**：K 线 / 财务等取数仍走 Router（`enabled` + `priority` 选源），`backtest-engine` 只消费其返回，不另建取数通道 | 否 |
| `tech-analyzer` | **复用**：MA60 等指标口径以 `tech-analyzer` 的确定性计算为准；校准题与「跌破 MA60」条件直接消费其指标，不重写一套指标 | 否 |
| `value-analyzer` | **复用**：规模 / 价值 / 质量类分组特征可取 `value-analyzer` 已算出的分位与原型（service/value），不重复造估值 | 否 |
| `trade-review-attribution` | **互补**：它复盘**已发生**的真实成交（FIFO 胜率归因），`backtest-engine` 模拟**未发生**的规则；两者不共享实现，也不互相替代 | 否 |
| `portfolio-analyzer` | **互补**：它算当前持仓集中度；`backtest-engine` 不产出持仓建议 | 否 |

`backtest-engine` 的**新增数据前置**（后复权价、成交额、涨跌停、停牌、退市 / ST、历史成分、分红）不通过修改上述 capability 的 spec 实现，而是在 `backtest-engine` 内声明「数据必须具备什么口径」；取数路径由 T2 `design.md` 决定，缺口显式报错而不是静默降级（见 R9 / R12）。

### Modified Capabilities

无。本次不改变任何既有 capability 的 spec 级行为；调用关系变化属实现细节。

## 成功标准（验收口径）

每条都可被 T4 逐条核对、被 T5 引用；判据是「命令输出 / 台账记录」而不是自评。

1. **校准题可复现（台子有资格说话的前置）**：以「跌破 MA60 卖出」为规则跑全 A（2015–2026 三段切分、扣全部成本、T+1、涨跌停顺延），输出显示其相对买入持有的超额**显著为负**（bootstrap 95% CI 不含 0，且报出 K 与校正后 p 值）。若复现不出该结论，`backtest-engine` 判定为不可信，**禁止**用它输出任何研究结论（飞书 §十）。
2. **台账可审计**：任一实验可用一条命令导出「假设 / 参数 / 样本区间 / K / 结果 / 是否触达样本外 / 预注册 commit」，字段齐全且与预注册文件逐字一致；事后修改预注册记录被拒绝（退出码非 0，台账留痕）。
3. **样本外只烧一次可机检**：同一假设第二次请求样本外区间时，系统拒绝执行并留痕（退出码非 0 + 明确提示「样本外已烧毁」），台账中该窗口「已消耗」标记唯一。
4. **成本与撮合可手算复算**：给定 1 笔样例成交（含涨停封板一次、停牌一次），输出的佣金 / 卖出印花税 / 滑点分项与手算一致（黄金样例断言）；封板当日订单状态为「失败并顺延」，且顺延目标日为下一个可成交日。
5. **无未来函数可证伪**：信号计算函数在输入上被限制为 t 日及之前的切片；任何尝试读取 t+1 及之后数据的路径必须抛错（负向用例通过），且财务字段按公告日而非报告期对齐有对应用例覆盖。

## 失败标准/反目标

任一条出现即本 change 失败：

- 把**策略结论**写成本 change 的交付物（如「-15% 止损有效 / 无效」「跌破 MA60 应该卖」）。本波只交台子；飞书 §一 的三个数字是**动机**，不是待验证结论的入库证据。
- 台子未通过 R18 校准，却用它输出研究结论，或把校准失败解释成「策略无效」。
- 预注册可事后修改、K 不报或事后补记、只报显著的那几个组合（多重比较灾难）。
- 用前复权价回测、用报告期当公告日、用今天的指数成分回看历史、把退市 / ST 股票剔除出样本（生存偏差）。
- 在 A 股语境下允许日内止损 / T+0、或假设涨停板上一定买得到、跌停板上一定卖得掉。
- 为了「跑出显著」而挑样本区间、切点或分组（后视镜分组）；把软标签（主题、产业链、管理层评价）直接放进回测分组。
- 让 LLM 生成或修改任何数值（收益、回撤、t 值、滑点、K）。
- 越界：改 `openspec/specs/`、写 `src/` `test/` 代码、产 `knowledge-delta.md`、改 `docs/mrd/`、伪造 MRD 锚点。

## Impact

- **新增代码模块**（T3 落地，本波不写）：`src/service/backtest/`（领域编排与纯函数信号）、`src/data_provider/` 下新增后复权 / 成交额 / 涨跌停 / 停牌 / 退市 ST / 历史成分的数据适配（子域归属由 T2 定）；`src/apps/` 增加 CLI 入口（`report backtest` 或等价子命令，名字由 T2 定）。
- **数据前置缺口（本波只登记，不修）**：
  - 复权口径：现有三源只有前复权（`src/data_provider/baostock/fetcher.py:363`、`src/data_provider/tushare/fetcher.py:295`、`src/data_provider/akshare/fetcher.py:109`），不满足 R9。
  - `kline` 表缺 `amount`（成交额）、涨跌停价 / 状态、停牌标记（`src/dao/models.py:134`），不满足 R7 / R8。
  - “财务按公告日对齐”缺表级 `ann_date`：财务数据落在 `stock_snapshots`（键为 `code, source, report_period`，`src/dao/models.py:31`），事件类表才有 `ann_date`（`src/dao/models.py:251`），不满足 R11。
  - 退市 / ST / 历史成分名单本机未见任何一手来源，不满足 R12（作为假设 A4 登记，答复前按「显式报缺口并停止」处理）。
- **配置**：`config/app.yaml` 需新增 `backtest` 段（费率、滑点分档、样本切分、门禁阈值、K 上报方式）；本波不改配置。
- **需同步更新的文档（由后续任务执行）**：`docs/dev/engineering-conventions.md` §3.1 / §3.2（新增 `service/backtest/` 子域，属架构变更）；`docs/design/references/README.md` 索引表补行；`docs/mrd/mrd-v1.md` 待 Owner 定稿后回填锚点。
- **依赖**：无新增第三方依赖（`pandas 3.0.2` / `numpy 2.4.2` 已装，见 `docs/agent-team/ENV.md`）；`matplotlib` 未安装，故本 change 不做图表产出。
- **风险**：① 数据前置缺口（后复权 / 成交额 / 退市 ST）可能使 R12 只能部分实现 → 已在 spec 中要求「显式报缺口并停止」，不静默降级；② 校准题的“显著为负”依赖样本区间与基准口径，判据已绑定 R3 / R13，变更需回到预注册流程。

## out of scope（本波明确不做）

- **策略研究结论**：不做「-15% 止损是否有效」「买点条件是否成立」等结论；这些是台子之上的实验，另立 change。
- **全市场荐股排序**（需要截面因子与全策略回测，飞书 §五「一期明确不做」）。
- **交易员自动下单**：只出工单，人工执行（飞书 §五）。
- **Web UI**：CLI 与对话足够（飞书 §五）。
- **宏观 / 政策研报、债券研究员**（飞书 §五）。
- **报告渲染**（Markdown / HTML / 飞书推送）：本 change 只产出台账与结构化结果，渲染归 `service/report` 既有能力。
- **全策略回测**（组合级逐日撮合 + 调仓规则同时上线）：MVP 只做事件研究（R17），全策略回测在其后。
- **数据侧修复**：不修 fetcher / 不新增数据表 / 不改 `openspec/specs/`（见 Impact 的「数据前置缺口」，由后续 change 承担）。
